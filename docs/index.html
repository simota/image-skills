ImageWhat should this picture say, and did the one that came back say it?

Six skills over image work — deciding what a picture must say, wording the request a generator receives, running it, changing what comes back, judging whether it is usable, and getting the file into a project. None of them generate pixels: that is Codex&rsquo;s own <code>imagegen</code> skill, and this is the discipline around it.

01What is loaded, and when it is paid for

A skill arrives in three stages and each costs something different. Almost every design rule in this repository follows from that asymmetry rather than from taste.

02The 6 skills

Each owns one kind of work and states it in its own Owns section. The tags under it are the facets recorded in image-registry/capabilities.yaml, which is also what the fixtures route against.

image-direction doc-write

What the picture is for, what it must say, and what it should look like saying it. It produces a brief a generator can be aimed at and a reviewer can judge against — never the wording that gets sent, and never a picture.

  • subject
  • mood
  • art-style
  • reference-analysis
  • composition-intent
  • brief
image-prompt doc-write

The request the generator actually receives — its structure, its exclusions, the canvas it asks for, and the set of variants that differ on purpose. It decides what is said, never whether the picture behind it was worth asking for.

  • prompt-structure
  • exclusions
  • aspect
  • variants
  • control-surface
  • prompt-record
image-generate full

The paid part. It invokes the generator, decides how many attempts the question is worth, records what each run was, opens what comes back, and names the one that survives. It does not write the prompt and does not place the file.

  • invocation
  • candidate-count
  • batching
  • recipe-capture
  • selection
  • cost
image-refine full

Everything done to a picture after one exists — a targeted edit, a reworked prompt, an extension, an upscale — and the discipline that keeps an iteration from drifting into a different picture. It does not decide whether the result is good enough; that judgement belongs to a reader who did not make the change.

  • regeneration
  • region-edit
  • object-removal
  • outpainting
  • upscale
  • iteration
image-review read-only

Looking at a picture and saying what is wrong with it, where, how badly, and whether it can ship. It writes nothing. That is the guarantee that makes it worth having: a stage that both judged and fixed cannot say which it did first.

  • artefact-detection
  • anatomy-and-text
  • off-brief-drift
  • severity-ranking
  • verdict
image-deliver full

The distance between a chosen picture and a file the project can use — format, the sizes the surface needs, compression, colour, name, placement, and the text that stands in for it when it does not load. It changes files, never pictures.

  • format
  • responsive-sizes
  • naming
  • compression
  • colour-profile
  • placement
  • alt-text

04Chains that recur

A chain of names expresses linear work only. Where a stage repeats until a condition holds, the entry carries the condition, the judge, and a hard cycle limit — without all three, “until it looks right” has no stopping rule and the loop ends when somebody gets tired.

RoutePatternWhenChainCondition
illustratelinear a picture is needed and nothing about it is decided yetimage-direction → image-prompt → image-generate → image-review → image-deliver gate · the brief names what the image is judged against before any prompt is written
one-offlinear the look is already settled and one picture is missingimage-prompt → image-generate gate · an existing image or brief is named as the thing this must match
asset-setlinear a family of images that must read as one setimage-direction → image-prompt → image-generate → image-deliver gate · what makes them a set is written down before the first is generated
repairlinear a picture that exists is wrong in a way someone can point atimage-review → image-refine gate · each finding names the region it is in before anything is regenerated
restylelinear the content is right and the look is notimage-direction → image-refine —
ship-existinglinear the picture is chosen and has to reach the projectimage-deliver —
look-checkreport-only is this image usable, and what is wrong with itimage-review stops at · one verdict with each defect located, ranked, and attributed to a cause. Nothing is regenerated
refine-to-briefloop iterate a candidate until it meets the brief or the budget stops itimage-refine → image-review oracle · no open defect at severity major or above, and one full pass over the image adds none

05The mechanism this set has and its siblings do not

Seven sets share one validator and one contract shape. Each declares exactly one signature mechanism, and that declaration is the whole difference — which is what keeps 7 copies of the same rules from becoming 7 dialects.

recipe · _image/RECIPE.md

A generated picture carries no history inside itself, so seven fields travel beside it — the engine, the model, the prompt verbatim, what was excluded, the size asked for and the size on disk, the inputs, the output. The generator exposes no seed, so a recipe fixes intent and never pixels: that gap is IRREPRODUCIBLE, stated once rather than papered over with a seed nobody has.

  • prompt

  • size

09Installing it

Each image-* directory is symlinked individually, so a skills directory keeps whatever else it already carries and a name already taken by a real directory is skipped rather than overwritten.

make link                       # into ~/.claude/skills
make link CLAUDE_DIR=.claude/skills

make check                      # the rules, then proof the rules still fire
make render                     # after editing a delivered block
make hooks                      # run the rules on every commit
  • Selection happens on the description alone. Every word that selects a skill appears literally in its description, and a rule checks the registry and the description still agree.
  • Contracts are delivered, not referenced. A rule kept only in _image/ is read on a minority of launches, so the operative part is copied verbatim into every skill and a rule fails if any copy has drifted.
  • Knowledge is split by whether it rots. Playbooks hold judgement and are budgeted; reference holds what goes stale, carries no line budget, and states what re-checks it instead of a bare date.
  • The fixtures do not model how a model chooses. They catch a missing or duplicated signal. Passing them is not evidence that nothing will be misrouted.
